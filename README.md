# Menu Mixer

Mac 메뉴 막대에서 앱마다 볼륨을 조절하는 네이티브 SwiftUI 앱입니다.

버전 **0.1.3**: Safari가 Cloudflare WARP로 표시되던 공용 WebKit 보조 프로세스 식별 문제를 수정했습니다. 0.1.1의 자동 재연결과 0.1.2의 로그인 시 자동 실행도 포함합니다. 이전 버전에서 ‘종료’를 누르고 새 앱을 실행하세요.

[GitHub 저장소](https://github.com/juh103/menu-mixer)

## 실행

실행에는 macOS 14.4 이상, 직접 빌드할 때는 Xcode Command Line Tools가 필요합니다. 외부 패키지는 사용하지 않습니다.

```sh
bash scripts/build-app.sh
open "build/Menu Mixer.app"
```

서명을 확인한 배포 파일은 `build/Menu Mixer.zip`입니다. 클라우드 동기화 폴더에서는 Finder/File Provider가 `.app`에 메타데이터를 붙여 엄격한 서명 검사에 영향을 줄 수 있어, ZIP은 `/private/tmp`의 임시 폴더에서 서명·검증한 후 만듭니다. ZIP을 로컬 폴더에 풀어 실행할 수도 있습니다.

1. 메뉴 막대의 슬라이더 아이콘을 누릅니다.
2. 음악이나 동영상을 재생합니다. 오디오를 사용하는 앱을 2초마다 갱신합니다.
3. 해당 앱의 스위치를 켭니다. macOS가 요청하면 시스템 오디오 녹음 접근을 허용합니다.
4. 슬라이더로 0–100%를 조절하거나 스피커 버튼으로 음소거합니다.
5. ‘모두 해제’ 또는 ‘종료’를 누르면 앱별 처리 경로를 제거합니다.

권한 거부 시 **시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 녹음**에서 Menu Mixer의 접근을 확인한 뒤 앱을 다시 실행하세요. macOS 버전에 따라 항목 이름이 다를 수 있습니다.

## 로그인 시 자동 실행

앱은 처음 실행할 때 Apple의 `SMAppService.mainApp`으로 로그인 항목을 등록합니다. 이후 로그인하면 메뉴 막대에서 실행되고 저장된 앱별 볼륨·음소거 설정을 복원합니다. macOS가 승인을 요구하면 앱의 ‘승인 필요’ 버튼으로 로그인 항목 설정을 열 수 있습니다.

메뉴 하단의 ‘로그인 시 자동 실행’ 스위치로 끌 수 있습니다. 이후 시스템 설정에서 사용자가 해제한 항목을 앱이 매번 강제로 다시 활성화하지 않습니다. ‘모두 해제’는 앱별 오디오 조절에만 적용되며 자동 실행 설정은 유지합니다.

설치 경로로 `~/Applications/Menu Mixer.app`을 권장합니다. 자동 실행을 사용할 앱은 삭제하거나 정리할 임시 폴더에 두지 마세요. 실제 로그아웃·재부팅 테스트는 별도로 필요합니다.

```sh
"$HOME/Applications/Menu Mixer.app/Contents/MacOS/MenuMixer" --login-status
"$HOME/Applications/Menu Mixer.app/Contents/MacOS/MenuMixer" --enable-login
```

`--login-status`는 상태만 읽고, `--enable-login`은 등록합니다. 두 명령 모두 오디오 처리를 시작하지 않습니다. `enabled`이면 종료 코드 0, 비활성/승인 대기는 2, 등록 오류는 1을 반환합니다.

참고: [Apple의 SMAppService 설명](https://developer.apple.com/documentation/servicemanagement/smappservice).

## 현재 구현 범위

- 메뉴 막대 팝오버, 앱 아이콘과 오디오 사용 상태
- 앱별 볼륨·음소거·조절 스위치 상태를 저장하고 다음 실행 때 자동 복원합니다. 이전 버전의 음소거 또는 100% 미만 볼륨 설정도 자동 복원 대상으로 가져옵니다.
- 여러 오디오 프로세스를 사용하는 앱은 정확한 PID의 정보와 실제 포함 앱의 번들을 기준으로 묶습니다. Safari와 WARP처럼 WebKit을 공유하면 해당 PID에 대해 macOS가 제공한 호스트 이름을 대조합니다. 유일한 소속 앱을 식별하지 못하면 원래 프로세스 이름을 표시하며 임의의 다른 앱으로 묶지 않습니다.
- 이전 버전이 `com.apple.WebKit.GPU`처럼 여러 앱을 합쳐 저장한 설정은 자동 적용을 해제합니다. 올바르게 분리된 Safari 또는 WARP 행에서 한 번 다시 설정해 주세요. Chrome 등 원래 앱 ID로 저장된 설정은 유지됩니다.
- 기본 출력 기기에서 재생되는 앱의 소리를 처리합니다. 앱 자체의 전용 출력 선택은 지원하지 않습니다.
- **단일 모노·스테레오 Float32 PCM 출력 스트림을 지원**합니다. 내장 스피커·유선 헤드폰·AirPods가 첫 검증 대상입니다. 다중 스트림·서라운드 장치는 지원하지 않습니다. 입출력이 결합된 기기는 물리 마이크 스트림을 비활성화하고 확인한 뒤 tap 입력만 사용합니다. 비활성화에 실패하면 시작하지 않습니다. Bluetooth 통화 모드·기기별 호환성은 실제 재생 검증이 필요합니다.
- 출력 기기·샘플레이트·채널 구성·앱 프로세스가 바뀌면 저장된 설정으로 경로를 다시 만듭니다. 앱이 잠시 사라지거나 재연결이 실패해도 스위치와 음소거는 유지합니다. 대기 중인 앱은 ‘설정 유지 · 재연결 대기’로 표시합니다.
- 사용자가 스위치를 끄거나 ‘모두 해제’를 누르면 자동 복원도 해제합니다. 앱 종료는 저장된 설정을 지우지 않습니다.
- 연결 상태는 2초 간격으로 확인하며 실패 시 2–16초 간격으로 재시도합니다. 기기 전환이나 경로 재생성 중에는 짧은 소리 끊김 또는 원래 소리 재생 구간이 생길 수 있습니다. 무중단 음소거를 보장하지 않습니다.
- DRM 등으로 캡처를 제한하는 콘텐츠는 지원을 보장하지 않습니다. OSStatus 성공만으로 실제 소리가 처리되었다고 판단할 수 없습니다.
- 로그인 시 자동 실행을 지원합니다. 로컬 개발용 ad-hoc 서명이며 배포용 Developer ID 서명·공증은 아직 포함하지 않습니다.

## 오디오 구조

Core Audio의 프로세스별 tap → 비공개 aggregate device(출력 기기를 클록 기준으로 사용) → C Float32 게인 처리 → 같은 콜백의 출력 버퍼로 재생합니다. 원본과 처리 음성이 겹치지 않도록 `mutedWhenTapped`를 사용합니다. 생성·시작 실패 시 부분적으로 만든 자원도 제거합니다. 시스템 기본 출력 기기 설정은 변경하지 않습니다.

오디오 콜백은 메모리를 할당하거나 잠금을 잡지 않습니다. 게인은 atomic 값으로 전달하고 한 버퍼 동안 부드럽게 변경합니다. 소리를 파일에 저장하거나 네트워크로 보내는 코드는 없습니다. 권한 요청은 사용자가 앱별 스위치를 켜고 첫 경로를 시작할 때 발생합니다.

참고: [Apple의 Core Audio taps 설명](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps).

## 확인 방법

```sh
bash scripts/test.sh
"build/Menu Mixer.app/Contents/MacOS/MenuMixer" --diagnose
```

DSP 테스트는 AddressSanitizer와 UndefinedBehaviorSanitizer를 사용해 채널 분리, 감쇠, 음소거 전환, 범위 제한, planar/interleaved 변환, 짧은 입력·누락된 입력 처리를 확인합니다. `--diagnose`는 출력 기기와 오디오 프로세스만 조회하며 tap을 만들거나 소리를 캡처하지 않습니다.

Swift 회귀 테스트는 실제 오디오 장치를 열지 않는 대체 경로로 다음을 검증합니다: Discord 통화 모드를 가정한 스테레오→모노→스테레오 전환 후 Chrome 음소거 유지, 출력 기기 변경, 오디오 프로세스 재생성, 재연결 실패와 재시도, 명시적 해제, 앱 재실행 시 설정 복원, 이전 설정 형식 호환성.

0.1.1에서 DSP 테스트와 설정·재연결 회귀 테스트 11개, release 빌드, ZIP 압축 해제 후 엄격한 코드 서명 검사와 버전·plist 검사를 통과했습니다.

0.1.2에서도 기존 DSP·회귀 테스트 11개와 release 빌드, ZIP 서명·버전 검사를 통과했고 설치된 앱의 로그인 항목 등록과 `enabled` 상태를 확인했습니다.

0.1.3에서는 Safari/WARP 분리, 프로세스 목록 순서 변경, 불명확한 호스트, 동일한 이름의 호스트, 현지화된 보조 프로세스 이름, 실제 포함 앱 우선 처리, Chrome 보조 프로세스 식별을 포함한 회귀 테스트 19개를 확인합니다. 읽기 전용 실기기 진단에서도 재생 중인 `com.apple.WebKit.GPU`를 `com.apple.Safari` / `Safari`로 식별하는 것을 확인했습니다.

실제 권한 허용·재생 검증은 별도로 필요합니다. 서로 다른 앱에서 소리를 재생하고 한 앱만 20%로 낮춰 다른 앱이 유지되는지, 음소거 후 이전 볼륨으로 돌아오는지, 종료·출력 기기 전환 후 원래 재생으로 복구되는지 확인하세요. 처리 도중 지연·끊김·이중 재생이 있다면 ‘모두 해제’로 처리 경로를 해제할 수 있습니다.

초기 버전 개발 시 읽기 전용 진단으로 AirPods Pro의 48 kHz 스테레오 Float32 출력과 Chrome 오디오 프로세스를 확인했습니다. 화면 자동화 도구가 시간 초과로 응답하지 않아 팝오버의 시각 검증은 완료하지 못했습니다. 실제 Discord 통화 입장·퇴장 중 소리 변화·지연·기기 전환 복구는 별도 수동 검증이 필요합니다.
